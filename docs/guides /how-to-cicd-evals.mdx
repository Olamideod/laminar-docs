# Run Laminar evaluations in CI/CD with GitHub Actions

Laminar evaluations tell you how well your LLM application performs against defined criteria. Running them automatically on every pull request keeps regressions out of production.

This guide shows you how to integrate Laminar evaluations into a GitHub Actions workflow. By the end, you will have a workflow that runs your evaluation suite on every pull request. It sends results to your Laminar dashboard and blocks merges when average scores drop below a threshold you define.

<Info>
  This guide assumes you know how Laminar evaluations work. If you are new to evaluations, read the [Tutorial: Trace a multi-step pipeline](/docs/guides/tutorial-trace-pipeline) first to build familiarity with the SDK before adding CI/CD.
</Info>

---

## Prerequisites

- Python 3.9 or higher
- A Laminar account and project API key
- An OpenAI API key
- A GitHub repository

---

<Steps>

<Step title="Write the evaluation file">

Create `eval/pipeline_eval.py` in your repository:

```python
import sys
from dotenv import load_dotenv
from lmnr import evaluate
from openai import OpenAI

load_dotenv()

client = OpenAI()


# The executor calls the function you want to evaluate.
# Replace this with your actual application logic.
def capital_of_country(data: dict) -> str:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[
            {
                "role": "user",
                "content": (
                    f"What is the capital of {data['country']}? "
                    "Answer with the city name only."
                ),
            }
        ],
    )
    return response.choices[0].message.content or ""


# Evaluators return a number between 0 and 1.
# Laminar records these scores and displays them in the dashboard.
def accuracy(output: str, target: str) -> int:
    return 1 if target.lower() in output.lower() else 0


# Collect scores to enforce a threshold gate.
scores = []


def accuracy_with_gate(output: str, target: str) -> int:
    score = accuracy(output, target)
    scores.append(score)
    return score


evaluate(
    data=[
        {"data": {"country": "France"}, "target": "Paris"},
        {"data": {"country": "Germany"}, "target": "Berlin"},
        {"data": {"country": "Japan"}, "target": "Tokyo"},
        {"data": {"country": "Brazil"}, "target": "Brasília"},
        {"data": {"country": "Australia"}, "target": "Canberra"},
        {"data": {"country": "Canada"}, "target": "Ottawa"},
    ],
    executor=capital_of_country,
    evaluators={"accuracy": accuracy_with_gate},
    name="capitals-eval",
    group_name="capitals",
)

# Exit with code 1 if the average score is below the threshold.
# This causes the GitHub Actions step to fail and blocks the pull request.
THRESHOLD = 0.8
if scores:
    average = sum(scores) / len(scores)
    print(f"Average accuracy: {average:.2f}")
    if average < THRESHOLD:
        print(f"Score {average:.2f} is below threshold {THRESHOLD}. Failing.")
        sys.exit(1)
    else:
        print(f"Score {average:.2f} meets threshold {THRESHOLD}. Passing.")
```

Run it locally to confirm it works before adding it to CI:

```bash
lmnr eval eval/pipeline_eval.py
```

**Expected output:**

```
Average accuracy: 1.00
Score 1.00 meets threshold 0.80. Passing.
```

</Step>

<Step title="Add a requirements file">

Create `eval/requirements.txt`:

```
lmnr>=0.4.0
openai>=1.0.0
python-dotenv>=1.0.0
```

</Step>

<Step title="Add secrets to your GitHub repository">

Your workflow needs two API keys. Store them as GitHub Actions secrets so GitHub never exposes them in logs or code.

1. Go to your repository on GitHub
2. Open **Settings > Secrets and variables > Actions**
3. Click **New repository secret** and add:
   - `LMNR_PROJECT_API_KEY`: your Laminar project API key
   - `OPENAI_API_KEY`: your OpenAI API key

<Warning>
  Secrets added to a repository are not available to pull requests from forks by default. If you are testing from a forked repository, add the secrets to the fork's own settings.
</Warning>

</Step>

<Step title="Create the GitHub Actions workflow">

Create `.github/workflows/laminar-eval.yml`:

```yaml
name: Laminar evaluations

on:
  pull_request:
    branches:
      - main

jobs:
  evaluate:
    name: Run Laminar evaluations
    runs-on: ubuntu-latest

    steps:
      - name: Checkout code
        uses: actions/checkout@v4

      - name: Set up Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.11"

      - name: Install dependencies
        run: pip install -r eval/requirements.txt

      - name: Run evaluations
        env:
          LMNR_PROJECT_API_KEY: ${{ secrets.LMNR_PROJECT_API_KEY }}
          OPENAI_API_KEY: ${{ secrets.OPENAI_API_KEY }}
        run: lmnr eval eval/pipeline_eval.py
```

Commit and push this file to a branch. Open a pull request against `main`.

</Step>

<Step title="Verify results in the Laminar dashboard">

After the workflow runs:

1. Open [lmnr.ai](https://lmnr.ai) and go to **Evaluations**
2. Click the `capitals-eval` run triggered by the pull request
3. Review per-datapoint scores in the results table
4. Use **Compare runs** to track score trends across pull requests

Every pull request that touches your LLM logic triggers a new evaluation run. Score history builds automatically.

**Expected output in the Actions tab:**

```
Average accuracy: 1.00
Score 1.00 meets threshold 0.80. Passing.
```

</Step>

</Steps>

## Troubleshooting

### The workflow fails with `LMNR_PROJECT_API_KEY not set`

Confirm the secret name in **Settings > Secrets and variables > Actions** is exactly `LMNR_PROJECT_API_KEY` with no extra spaces. Confirm the `env` block in the workflow file references `${{ secrets.LMNR_PROJECT_API_KEY }}`.

### The workflow exits with code 1 but answers look correct

Open the **Evaluations** tab in the Laminar dashboard. Expand the failing run and inspect the `output` column for each datapoint. Identify which rows returned wrong answers. If the issue is intermittent, increase the dataset size. One wrong answer has less impact on the average when the dataset is larger.
